## Framing

Commercial inference routing is a real product category with real economic logic. Inference cost curves diverge sharply across tiers — a query served by a small open-weight model costs orders of magnitude less than the same query served by a top-tier proprietary model. Routing decides per-request which tier the query needs. Products like Abacus RouteLLM (surveyed 2026-07-11) commercialize this: an OpenAI-compatible endpoint accepts a `route-llm` model identifier and dispatches internally based on the provider's classifier. The commercial pitch is cost efficiency without operator cognitive overhead. The pattern is spreading — OpenAI's o1-vs-o1-mini automatic depth selection, OpenRouter's model marketplace, and every next-generation Router product will have some version of this shape.

The pattern composes badly with substrates that treat Regent as an identity-bearing cognitive presence. Silent model swaps break the *A model and its prompts are an atomic pair* invariant. Chain-anchored precedent gets under-labeled — a precedent under `route-llm` may have been served by any of a dozen underlying models, and precedent generated by model X may not transfer to model Y. Cognitive Self-Observer loses ground truth — it verifies claims against known-model behavior, and cannot distinguish "the pinned model confabulated" from "the router routed this to a cheaper tier that misinterpreted." Operator's authority over "the Regent" as a specific cognitive presence dilutes silently.

The substrate's answer is not "reject all routing." Routing that cost-optimizes within an operator-declared envelope, with chain-anchored evidence of every routing decision, composes cleanly with our discipline. The substrate's answer is "make routing decisions chain-anchored and operator-authorized."

Three properties frame the discipline:

1. **The served model is chain-anchored, always.** Every inference response's actual served-model identity is recorded in the substrate's chain, not the requested model. Silent routing under identity-bearing cognition becomes structurally impossible.
2. **The routing envelope is operator-declared, via ceremony.** Operator declares — via CloudMandate-composed ceremony — which models the Regent's cognition may be served by. Substrate-side selection within the envelope; no silent expansion by the provider.
3. **Route-cost efficiency is available, but only within operator authority.** Substrate can use routing productively when operator has explicitly authorized the routing envelope. Substrate does not use routing when operator has pinned to a specific model. Provider chooses routing tactics; operator chooses routing strategy.

## The three configurations analyzed

### Configuration 3 — Rendered model identity in every response (provider-cooperative)

Every commercial routing provider following OpenAI's response conventions returns a `model` field indicating which model actually served the request. Abacus RouteLLM's API documentation explicitly commits to this: *"The model used for the completion (may differ from the requested model if using route-llm)."* OpenRouter behaves similarly. Any provider claiming OpenAI compatibility that omits this field is out of compliance.

Substrate reads the response's `model` field on every inference call and chain-anchors it. Implementation is minimal:

- Regent's inference wrapper parses the response, extracts the `model` field
- Emits `regent:inference:served:<model_id>` receipt as part of every completion
- If served model differs from requested model, additionally emit `regent:inference:routed:from=<requested>:to=<served>` receipt
- Cognitive Self-Observer's ground-truth verification uses the served-model identity, not the requested-model identity
- Chain-anchored precedent references the served model directly

This alone closes the biggest trust gap. Silent model swaps become chain-visible. Requires no provider cooperation beyond standard OpenAI-compatible response format. Ships today.

### Configuration 2 — Substrate-side envelope with operator authority

Operator declares — via ceremony composed with CloudMandate — a set of authorized models the Regent's cognition may be served by. Substrate-side classifier selects per query. Every routing decision is chain-anchored per operator's declared policy.

Ceremony shape:
- Operator emits `regent:inference:envelope_declared:<envelope_id>` receipt with:
  - Set of authorized models (e.g., `["claude-sonnet-4-6", "claude-opus-4-8", "gpt-5.4"]`)
  - Optional operator-declared routing policy (cost-optimize / capability-optimize / latency-optimize / custom)
  - Optional cost caps and per-model quotas
  - CloudMandate cross-reference for provider authorization
- Substrate-side classifier receives operator envelope, current query, and returns per-query decision
- Regent's inference call targets the substrate-selected model directly (specific model name, not `route-llm`)
- Response's `model` field verifies the substrate's selection was honored

This is provider-independent. Works over any OpenAI-compatible inference provider — Abacus RouteLLM (calling specific models bypasses their router), OpenRouter (same), direct provider access (Anthropic, OpenAI, Google, xAI), on-prem models. The substrate-side classifier can be a small local model or a rule-based policy; classifier decisions are themselves chain-anchored.

Composes with MODEL-DOSSIER-2026-07.md (canonical dossier spec, consumed by EAM Phase 5 empirical program) — the envelope is a set of dossiered models, and the classifier picks among them per operator-declared policy.

### Configuration 1 — Router as informational, not authoritative (provider-dependent, not currently offered)

Provider returns classifier verdict as metadata; substrate authorizes routing decision before the query is served. This is not currently offered by any commercial routing provider surveyed. Would require either a feature request to the provider or the substrate-side classifier from Configuration 2 — which subsumes it. Documented here for completeness; the substrate implements Configuration 2 as the substrate-native answer to Configuration 1's shape.

## What the substrate ships

### Layer 1 — Configuration 3, immediate

Every inference call, from substrate startup forward, chain-anchors the response's served-model identity. Implementation is a substrate patch, not a design commitment. Applies whether operator uses `route-llm` (routing enabled) or pins to a specific model (routing disabled).

Receipt schema:

```
regent:inference:served
  fields:
    session_id: <uuid>
    turn_id: <uuid>
    requested_model: <string>       # what substrate asked for
    served_model: <string>          # what actually served (response.model)
    provider: <string>              # abacus / openrouter / anthropic / etc.
    endpoint: <url>                 # provider endpoint used
    token_usage: {prompt, completion, total}
    latency_ms: <int>
    timestamp: <iso8601>
    signature: <ed25519 over content>
```

Divergence receipt (when served ≠ requested):

```
regent:inference:routed
  fields:
    session_id: <uuid>
    turn_id: <uuid>
    from: <requested_model>
    to: <served_model>
    envelope_authorized: <bool>     # was this within operator's envelope?
    signature: <ed25519 over content>
```

If `envelope_authorized == false`, the substrate additionally emits a warning receipt and Cognitive Self-Observer flags the response as authority-violated. Depending on operator's declared severity, this may trigger a Circuit Breaker escalation.

### Layer 2 — Configuration 2, deliberate build

Operator-declared inference envelope with substrate-side selection. Ceremony-anchored per Envelope changes. Requires:

- Envelope declaration ceremony (composed with CloudMandate)
- Substrate-side classifier runtime (`crates/zp-regent/src/inference_classifier.rs`, advisory-only until envelope ceremony ships)
- Per-decision chain-anchoring (`regent:inference:classifier_decision:<decision_id>`)
- Envelope-versioning discipline (envelope changes are ceremony receipts)
- Model dossier integration (classifier's decisions weighted by dossier evidence)

Not immediate. This is the design commitment operator makes when they want cost efficiency without provider-owned routing. Substrate can be shipped in Layer-1-only mode indefinitely — operator pins to a specific model, no routing, no envelope. Layer 2 unlocks cost efficiency when operator has determined some query classes don't need top-tier depth.

### Routing policy: the precedent bright-line

Amended 2026-07-18 following SLM failure-mode analysis. Resolves part of open position "Substrate-side classifier design" for the SLM-vs-LLM tier decision (leaves policy for within-tier decisions open).

The substrate ships a canonical bright-line for classifier decisions when the envelope contains both edge-scale SLMs (local Ollama, 350M–24B) and frontier LLMs (rally or cloud mandate):

**Precedent → SLM. Novelty → LLM.**

Concretely: for each cycle, before dispatch, the classifier queries the chain for prior `regent:remediation:*` and `regent:precedent:*` receipts matching the current cognitive input's (task_class, finding_type, capability_class) tuple. If precedent exists AND the precedent is operator-signed (or established via act-on-precedent per CLAUDE.md heuristic), route to SLM tier. If no precedent exists, or the current context is materially different from prior precedent (per act-on-precedent's context-novelty test), route to LLM tier.

**Rationale.** SLMs excel at pattern matching against known corpora — tool orchestration where the tool set is stable, structured emission where the schema is fixed, precedent-based reasoning where "same class of problem, similar shape of solution" is the pattern. LLMs excel at novel-context reasoning — precedent-setting, ambiguous specifications, adversarial analysis, cross-domain synthesis. Routing precedent to SLM preserves LLM budget for the cases where LLM capacity actually matters; routing novelty to LLM prevents SLM doom loops (per REGENT-DOOM-LOOP-DETECTION-2026-07.md) on tasks structurally beyond SLM capacity.

**Composition with act-on-precedent.** The routing bright-line is `act-on-precedent, escalate-on-novelty` applied to model tier selection. Same three-part test:
1. Does chain evidence show this class of task has been handled before? If yes, SLM handles it.
2. Is the operator-signed precedent still applicable (not superseded, not revoked)? If yes, SLM handles it.
3. Is the current context materially different from prior precedent (co-occurring findings, novel environmental state)? If yes, escalate to LLM tier even if the task class is known.

All three pass → SLM. Any fails → LLM. Chain-anchored per decision as `regent:inference:tier_selected` with the precedent-lookup evidence.

**Interaction with doom-loop detection.** If the SLM tier hits Class R2 (confirmed doom loop) on a task the classifier routed there based on precedent, that's structural evidence the precedent's context-novelty test missed something. Emits a `regent:precedent:context_novelty_missed` receipt citing both the doom-loop receipt and the precedent receipt. Feeds back into the classifier's future decisions: same (task_class, prior-precedent) tuple gets escalated to LLM until operator reviews the drift.

**Bootstrap policy.** Fresh operator with no precedent chain → every cycle escalates to LLM tier until precedent accumulates. This is consistent with the substrate's overall thesis: the operator's trust corpus (chain) grows empirically; a fresh substrate has no accumulated context to route from. Cost implication: first N cycles on cloud tier, cost decays as precedent chain grows and more cycles route to local SLM.

**What this does NOT decide:** within-tier routing (which SLM among several, which LLM among several) remains an open position. The classifier design (rule-based, small-local-model, Regent-adjacent cognition) remains open. This bright-line resolves only the tier decision.

Composes with REGENT-DOOM-LOOP-DETECTION-2026-07.md, act-on-precedent heuristic (CLAUDE.md), COGNITIVE-INPUT-PLANE-2026-07.md (matrix's context feeds the classifier's precedent query), and SHADOW-EVALUATION-PRIMITIVE-2026-07.md (candidate SLM tier can be shadow-evaluated against LLM tier on same task class to inform routing policy refinement).

### What the substrate does not do

- **Silent routing under identity-bearing Regent cognition.** Never. Regardless of provider capability or operator authorization structure, Regent's cognitive cycles are served by a model whose identity is chain-anchored on every call. Provider `route-llm` may be used only when operator has declared an envelope authorizing it.
- **Trust provider classifier decisions unverified.** The provider's routing is opaque to us. Even under Configuration 3 (rendered model identity), the substrate treats provider routing decisions as evidence to be verified — did the served model come from operator's envelope? Is Cognitive Self-Observer's confidence in the response consistent with the served model's dossier? Chain-visible discrepancies feed into circuit-breaker escalation.
- **Silently degrade model tier under load or cost pressure.** If envelope authorizes only tier N and tier N is unavailable, substrate reports the outage to operator; does not silently substitute tier N-1.

## Cognitive horizon — the second routing axis (added 2026-07-22)

The precedent bright-line above resolves the **capability axis** (SLM vs LLM) and, as "What this does NOT decide" states, *only* the tier decision. Real routing needs a second, orthogonal axis: **cognitive horizon** — whether a cognitive task is *realtime* (an operator, or an operator-facing surface, is blocked on the result) or *non-realtime* (the result lands on the chain for later consumption). Motivated by the Measured note below and by `AI-LANDSCAPE-SIGNAL-2026-07.md` Signals 2–3: the local-frontier floor is a **latency (prefill) floor, not a capability floor**, so the substrate routes by latency-tolerance as well as by capability.

### The routing matrix

Horizon × capability, with the cells the substrate assigns:

| | precedent (known class) | novelty (novel context) |
|---|---|---|
| **realtime** (operator waiting) | local SLM — fast, cheap (today's bright-line) | rally / cloud frontier — needs speed *and* capability |
| **non-realtime** (chain-consumed) | local SLM | **local-high — sovereign frontier, slow-but-yours** |

The load-bearing cell is **non-realtime × novelty**: deep reasoning that today defaults to expensive cloud frontier can instead run on the operator's own metal (disk-streaming or big-UMA local frontier), slowly, because nobody is blocked on it. This collapses cloud/rally to **realtime novelty only** — the narrow case that needs both speed and frontier depth — dramatically shrinking the `DEPENDENCY-POSTURE` Tier-3 cognition-layer surface.

A third axis surfaced in adversarial review governs the escalation valve: **escapability** — *may-egress* vs *sovereign-only*. The highest-value non-realtime work (whole-chain reflection over the operator's corpus) is sovereign-only: escalating it to cloud on a deadline would egress the very thing local-high exists to protect. So sovereign-only work never escalates; it degrades scope or accepts staleness instead.

### Why this is sovereignty, not just cost

The non-realtime horizon is disproportionately the substrate's deep reflection over the operator's *whole accumulated chain and ontology* — the most sensitive aggregate the substrate holds. Running it local-high means the substrate's self-understanding never leaves the operator's machine. This is aligned-blindness / data-sovereignty (composes with `SUBSTRATE-BLINDNESS-HEURISTICS-2026-07.md` and `CRYPTOGRAPHIC-SOVEREIGNTY-AND-LEGAL-PROCESS-2026-07.md`), not merely a latency optimization: the substrate reflects on the operator privately, on the operator's own metal, and only rents a brain for interactive novelty.

### Horizon classification — a property of who is waiting

A task's horizon is set by who consumes its result, mapping onto `SUBSTRATE-COORDINATION-DISCIPLINE-2026-07.md`'s priority hierarchy:

- **realtime** — an operator or operator-facing surface is blocked (priorities 1–2): live directives, interactive tool dispatch.
- **non-realtime** — the result lands on the chain for later use (priorities 3–4): Cartographer ontology materialization, the long observer window, shadow-evaluation, digest/candidate generation, deep analysis of already-flagged items.

Two bright lines at the edges:

- **Gating checks are near-realtime, not background.** Claim Verifier (pre-emission) and Cognitive Self-Observer (post-emission) sit on the emission critical path; they must not be routed to a slow horizon even though they are "internal."
- **Split monitoring from analysis.** Aegis's *watch* must be timely (fast/shallow — a detection stale by 30 minutes is not detection, contra *detectability over invulnerability*); local-high is reserved for deep *analysis* of items the fast watch has already flagged.

Per-process horizon is an operator-declared property in the inference envelope (P9 keeps horizon-routing strategy operator-authorized).

### Disciplines

1. **Deadlines — non-realtime is not unbounded.** Each non-realtime process declares a latency-tolerance class and a soft deadline. When a deadline is at risk: *escapable* work escalates to a fast tier — this is the **fallback envelope** open position, now defined for the escapable case; *sovereign-only* work degrades scope or accepts staleness and **never egresses**. Composes with commitment receipts (`check-at` / `promised-action`) and the chain-watcher.
2. **Harmony / yield.** Local-high inference is heavy (RAM, NVMe, GPU, thermal/power). It must yield to operator-facing realtime work — checkpoint at token/expert boundaries, and gate sweeps on power and thermal state via `HARDWARE-OBSERVER-2026-07.md`. Per `SUBSTRATE-COORDINATION-DISCIPLINE`, background cognition is autonomic and defers to operator flow. On a single device, realtime *suspends* background; clean non-degrading operation implies a fleet — the local-high tier belongs on a rally target (`MULTI-DEVICE-OPERATION-2026-07.md`), not the operator's active device.
3. **Calibration — don't let a degraded local model quietly pollute precedent.** Local-high (especially quantized) feeds the ontology and self-observation findings that *become* precedent. Periodically shadow-compare local-high against a control target to measure fidelity (`SHADOW-INFERENCE-COMPARISON-2026-07.md` Triggers 2 and 4), and mark local-high outputs that feed precedent as **provisional** until calibrated — reusing the novel-model quarantine posture above. Silent quality degradation is the failure mode this guards; APOLLO measurement found int4 grounded-retrieval did *not* degrade, but the calibration discipline is what keeps that a verified fact rather than an assumption.

### Receipts

- `regent:inference:horizon_classified` — per cognitive task, fields `{horizon: realtime|non_realtime, escapability: escapable|sovereign_only, deadline_soft, process_class}`. Chain-anchored; feeds the substrate-side classifier alongside `regent:inference:tier_selected`.
- `regent:inference:horizon_escalated` — an escapable non-realtime task hit its deadline and was escalated to a fast tier; cites the missed deadline.
- `regent:inference:horizon_degraded` — a sovereign-only task hit its deadline and reduced scope or accepted staleness rather than egress; records what was dropped (no silent truncation).

### Open positions this resolves / advances

- **Substrate-side classifier design** → *measured.* A Qwen3-1.7B (Apache-2.0, clear-license) implements the classifier at ~206 tok/s, 4/4 reliability run thinking-off (Measured note). The classifier now emits both a tier and a horizon decision.
- **Fallback envelope** → *defined* for escapable non-realtime work (escalate on deadline risk), with a new bright-line for the sovereign-only case (degrade, never escalate/egress).
- **Within-tier routing** → *partially:* horizon selects local-high vs local-SLM within the local tier.

Still open: whether horizon is operator-declared per process vs inferred by the classifier; deadline-tolerance defaults per process class; and calibration cadence for the local-high tier.

### Empirical grounding (APOLLO)

The matrix is measured, not theoretical (`tools/local-model-bench/`, `LOCAL-MODEL-SELECTION-2026-07.md`): the realtime tiers are interactive on APOLLO (Qwen3-30B-A3B and 4B at ~93 tok/s, 4/4 emission); non-realtime local-high reflection is feasible and correct through a 64k corpus but prefill-bound (~6 min to prefill 64k), which is precisely why it belongs off the realtime path; and memory is abundant (22.6GB of ~56GB at 64k), so the ceiling is prefill *time*, not capacity.

## Novel model handling

Commercial routing providers throw curve balls. Abacus adds new models to their catalog on a weekly cadence; OpenRouter lists dozens; provider-side updates ship silently. When `route-llm` routes to a model the substrate has no dossier for — or when operator adds a new model to the envelope before its dossier is built — the substrate must handle the novel-model case explicitly. Silent acceptance defeats the purpose of Cognitive Self-Observer's model-conditioned verification. Silent rejection defeats the purpose of routing at all.

The discipline treats novel model service as a **substrate admission event** — same shape as QUARANTINE-PLANE-2026-07.md's admission of new artifacts, applied to cognitive-input model identity. Three phases:

### Phase 1 — Detection

On every inference response, the substrate checks the served-model identity against its dossier registry. If the served model has no dossier entry:

- Emit `regent:inference:novel_model_served:<model_id>` receipt on the chain
- Response is treated as **provisional cognition** — accepted for the immediate operator interaction (not lost), but marked with reduced trust and quarantined from precedent-accumulation
- Cognitive Self-Observer's verification runs but its confidence is degraded; ground-truth checks against dossier are unavailable, so semantic verification against operator-declared standing corrections is what carries the check
- Regent surfaces the novel-model event to operator on next narrated response (or immediately, per operator's declared novel-model preference)

Under Layer 1 alone (no envelope declared), novel-model service is expected — the provider is authorized to route wherever they will. Detection is the substrate's mechanism for keeping the operator aware of what's actually happening.

Under Layer 2 (envelope declared), novel-model service is an anomaly. The classifier only calls specific model names within the envelope. If the response returns a served model outside the envelope, something is wrong — the provider is lying about the served model, or the provider ignored the specific model request, or the classifier was compromised. Emit `regent:inference:envelope_violation:<served_model>` receipt; Circuit Breaker triggerable per operator's declared severity.

### Phase 2 — Quarantine and provisional-dossier accumulation

Between novel-model detection and operator disposition, subsequent inference calls to the novel model (if any) are:

- Accepted, but each response emits a `regent:inference:provisional_service:<model_id>:<call_id>` receipt
- Response content is chain-anchored but precedent-value is quarantined — not admissible into Cognitive Input Plane's precedent tier
- Cognitive Self-Observer runs behavioral probes (per operator preferences): does the response exhibit patterns consistent with the model's declared family? Does it fail known-answer verification? Are refusals aligned with expected policy?
- Behavioral evidence accumulates into a provisional dossier fragment (`model:dossier:provisional:<model_id>`)

**Shadow-inference comparison** (per SHADOW-INFERENCE-COMPARISON-2026-07.md) is the substrate's canonical mechanism for building provisional dossier evidence: novel-model service is Trigger 1 in the shadow-inference primitive; parallel dispatch against operator's declared control target produces comparative evidence for the provisional dossier; disposition mode (shadow / substitute / divergence-gated / convergent-only) is operator-declared per envelope; cost budget is chain-anchored. Novel-model discipline delegates the comparative-evidence mechanism to the shadow-inference primitive rather than reinventing it.

The substrate does not silently promote novel models to full-dossier status based on accumulated evidence alone. Promotion is ceremony.

### Phase 3 — Operator disposition

Operator has four canonical responses to novel-model detection:

- **Bootstrap dossier**: authorize the bootstrap ceremony per MODEL-DOSSIER-2026-07 §"Bootstrap ceremony" (running under EAM Phase 5 empirical program authority). Substrate runs the model against the full evaluation battery (intent classification, sovereign identity, adversarial resistance suite, think-suppression profile, model-prompt coupling probes). Chain-anchored evaluation receipts produce a full dossier. Model becomes envelope-eligible.
- **Add to envelope with provisional dossier**: accept model for use with the provisional dossier as its trust basis. Documented reduced-trust posture. Suitable when operator has independent knowledge of the model and doesn't need full evaluation battery.
- **Reject and quarantine**: add model to negative envelope — the classifier explicitly refuses to select this model; if the provider routes to it anyway, envelope-violation emergency response triggers. Emit `regent:inference:model_rejected:<model_id>` receipt.
- **Reject provider**: broader response — the fact that this provider routed to an unauthorized model is a peer-trust-anchor concern. Operator may revoke provider CloudMandate entirely.

Substrate surfaces novel-model detection with recommended disposition (informed by provisional dossier evidence if any accumulated). Operator's disposition is chain-anchored via ceremony.

### Composition with Quarantine Plane

Novel model handling is a specific instance of QUARANTINE-PLANE-2026-07.md admission discipline applied to model identity. Same five-step ceremony flow: intake (provider serves the novel model) → verification (provisional dossier accumulation) → operator delegation (bootstrap ceremony authorization) → admission (dossier ratification and envelope addition) → asymmetric revocation (operator can revoke admission unilaterally). The dossier is the admission's chain-anchored evidence.

Under this composition, Regent's cognitive substrate treats "novel model served" the same way the observation plane treats "unknown listener detected" — default-deny at trust, chain-anchor for evidence, provisional-tier-only until operator ceremony admits or rejects.

## Attack model

- **Provider silently routes to cheaper model to reduce their cost**: Configuration 3's rendered-model field catches this. If provider's response `model` field is dishonest, Configuration 2's substrate-side selection bypasses the router entirely.
- **Attacker compromises provider to serve malicious model output**: substrate cannot verify model integrity of provider responses. Envelope-narrowing (specific model + specific provider) minimizes surface; reproducibility ceremony over test queries can detect gross divergence.
- **Attacker manipulates operator to declare over-broad envelope**: envelope declaration is operator ceremony. Substrate surfaces envelope scope clearly. Operator judgment remains authoritative; substrate cannot replace it.
- **Attacker exploits routing divergence to inject prompt from a different model's context window**: served-model identity chain-anchored per turn. Cross-turn context injection detected by turn-boundary discipline.
- **Attacker forces silent tier degradation via provider outage**: substrate reports outage to operator; does not silently substitute. Operator decides whether to authorize substitution or defer work.
- **Attacker manipulates substrate-side classifier**: classifier decisions chain-anchored. Anomalous classifier patterns detectable. Classifier can be replaced or its decisions overridden via ceremony.
- **Provider changes underlying model identity behind stable name (silent version drift)**: provider's naming is opaque to substrate. Model dossiers (per MODEL-DOSSIER-2026-07 §"Continuous drift signal", operated on by EAM Phase 5's empirical program) detect behavioral divergence; substrate flags dossier-inconsistency for operator review.
- **Provider routes to novel/unreleased/experimental model**: novel-model detection triggers; response quarantined from precedent; operator ceremony required for admission. Substrate treats this as expected commercial-provider behavior — Abacus adds models weekly — not as attack, but as admission event requiring operator authorization.
- **Attacker exploits novel-model quarantine to force degraded posture**: if attacker can trigger novel-model responses at scale, Regent's cognition operates in quarantine posture (provisional cognition, no precedent accumulation). Substrate reports the sustained-novel-model pattern to operator; may propose emergency envelope-narrowing to a known-good pinning until investigation.
- **Novel model's provisional dossier is manipulated by attacker's queries**: provisional dossier accumulation is bounded — behavioral probes are operator-declared, not attacker-controllable. Ratification ceremony requires operator judgment on the accumulated evidence, not automatic promotion.

## Failure modes

- **Provider response omits `model` field**: substrate falls back to requested-model as served (with reduced confidence flag). Emits `regent:inference:model_field_missing:<provider>` receipt so operator can track providers that fail this discipline.
- **Envelope specifies unavailable model**: substrate reports outage; operator decides whether to authorize fallback via ceremony. Not silent.
- **Classifier picks unauthorized model due to bug**: attempted call to unauthorized model rejected pre-emission via substrate delegation check. Emits classifier-error receipt.
- **Envelope grows unbounded via successive ceremony additions**: operator UX surfaces envelope size at ceremony time. Reasonable envelope sizes (2-5 models) recommended.
- **Model dossier stale for envelope model**: envelope entry with stale dossier triggers dossier-refresh ceremony proposal by substrate.
- **Precedent under superseded model**: precedent chain-anchored under prior model version. Cognitive input plane weights precedent by model-version distance. Older precedent under obsolete model → lower weight.
- **Novel model served with no dossier available**: response accepted as provisional cognition; quarantined from precedent; operator disposition required. Substrate does not silently promote to full trust based on accumulated behavioral evidence alone.
- **Novel-model quarantine posture sustained (many calls with no operator disposition)**: substrate surfaces the pattern to operator with increased urgency after N calls or T time; may propose emergency envelope-narrowing to prevent extended provisional operation.
- **Provider promotes model behind stable-model name (silent version-bump)**: dossier-behavioral-drift detection catches when the same name starts exhibiting different behavior. Composes with novel-model handling — the "same name, different behavior" case is treated as if the model were novel until dossier-refresh ceremony reconciles.

## Non-goals

- **Not a substitute for CloudMandate**. CloudMandate authorizes provider access at operator's outer scope. This spec elaborates how the substrate uses that access without ceding routing authority to the provider.
- **Not universal routing intelligence**. Substrate-side classifier is operator-declared, not universally clever. Sophistication of classifier is operator choice.
- **Not cost-optimization by default**. Substrate defaults to pinning (identity-consistent, no routing). Cost efficiency is an opt-in operator ceremony.
- **Not automatic envelope adjustment**. Substrate does not autonomously add or remove models from envelope based on cost or capability signals. Envelope changes require operator ceremony.
- **Not model version pinning enforcement**. Provider version drift is beyond substrate control; dossier-inconsistency flagging is the detection mechanism.

## Framing note

Inference Routing Discipline is the substrate's structural response to the commercial routing pattern that's already reshaping the LLM ecosystem. Same principle as chain-anchored discipline elsewhere — operator authority chain-anchored per decision, provider tactics operating within operator strategy, ground truth preserved for post-hoc verification.

The load-bearing insight: **the substrate supports routing, does not rely on it, and never lets routing be silent.** Routing is a real economic optimization worth capturing when operator has authorized it. Silent routing is a trust-chain break the substrate refuses regardless of economic pressure. The two-layer discipline (served-model chain-anchoring immediately, operator-declared envelope deliberately) gives the operator every combination they might want — from full-pinning-no-routing (identity-consistency prioritized) through envelope-with-substrate-classifier (cost-efficient with authority preserved) to eventual future provider-cooperative informational routing when that shape becomes available.

Combined with the substrate's structural discipline across every trust boundary, inference routing discipline completes the cognitive-sourcing envelope. What was previously implicit — Regent's cognition is served by "the API" — becomes structural: served-model chain-anchored, envelope operator-declared, classifier decisions ceremony-visible. Sovereignty is preserved because operator authorizes every routing decision (via envelope) and can inspect every routing decision (via chain). Safety is preserved because Cognitive Self-Observer knows what model actually produced each claim. Continuity is preserved because chain records the specific cognition-producing model per turn, enabling precedent-transfer to reason across models rather than assume homogeneity. The substrate composes with the commercial routing pattern without ceding its trust properties to the commercial provider.

## Measured note (2026-07-22) — APOLLO benchmark data-backs the routing economics

Promotes the held **E1** nomination from `AI-LANDSCAPE-SIGNAL-2026-07.md` §1 (and its Signal-2 refinement) from assertion to measurement. Benchmarked on APOLLO (M4 Pro Mac Mini, 64GB, ~273GB/s) via `tools/local-model-bench/`; full data in `LOCAL-MODEL-SELECTION-2026-07.md`.

**The local-frontier floor is a *latency* (prefill) floor, not a capital/capability floor — now measured.** A clear-license Qwen3-30B-A3B (Apache-2.0) runs as an *interactive* resident Regent: ~93 tok/s decode, 4/4 structured emission (receipt / tool-call / route-classifier / synthesis), int4-correct grounded reasoning, and correct 64k-corpus needle-synthesis — resident in 16GB with memory to spare (22.6GB of a ~56GB budget at 64k). Decode is not the bottleneck; **long-context prefill is** (≈790 tok/s at 4k falling to ≈180 tok/s at 64k — ~6 min to prefill a 64k corpus). This confirms the routing bright-line as the *economic and latency* answer, not merely capability: precedent-shaped and interactive work runs cheap and fast on local models; whole-chain reflection is prefill-bound and belongs on the non-realtime horizon.

**Layer 2's substrate-side classifier now has a measured, clear-license implementation.** A Qwen3-1.7B (Apache-2.0) handles the SLM-vs-LLM routing decision at ~206 tok/s with 4/4 structured reliability — *when run at its correct operating point* (thinking disabled; a model and its prompts are an atomic pair). Configuring the model correctly first, rather than testing conformance to a shared default, moved it from a false 2/4 to a true 4/4 — a discipline the classifier runtime must honor: emit terse verdicts with thinking off.

Net: the substrate-side classifier (fast local), precedent→SLM (30B-A3B / 4B, interactive), and novelty→rally/cloud tiers are all measured and clear-license on APOLLO. Local inference is not a fallback of last resort; it is a capable, interactive, sovereign default.
