# Canonical Corpus Index

Established 2026-07-10. This document is the ongoing map of the ZeroPoint corpus. Updated whenever a canonical elaboration lands or a doc reclassifies. It is the single source for "which docs are canonical, which are historical, and where each fits in the hierarchy."

## The four-tier hierarchy

**Tier 1 — Canonical spec.** The substrate's declared canonical truth. Singular. Non-narrative structured artifacts (once tooling exists) plus the narrative that generates them.

**Tier 2 — Canonical elaborations.** Design docs that elaborate specific Tier 1 sections with implementation-level detail and design rationale. Each declares which KEEL section(s) it elaborates. Updated when the substrate's design evolves. Canonical for their scope; not competing with Tier 1.

**Tier 3 — Historical corpus.** Prior architecture docs and design notes predating the July 2026 KEEL declaration, or superseded by later work. Retained for the reasoning trail — how we got here, what was learned along the way, findings from specific incidents (pentest results, sprint outputs, historical decisions). **Not amended for corpus pivots.** Frozen at authoring frame.

**Tier 4 — Working principles.** Behavioral rules for how work happens, not substrate claims. Live in `CLAUDE.md`. Include the working principles (Karpathy-style), workflow heuristics, tone preferences, and empirical-program locks.

- **[`design/INFORMATION-CUSTODY-TIERS-2026-08.md`](design/INFORMATION-CUSTODY-TIERS-2026-08.md)** — elaborates KEEL §III.24 (aligned blindness), §II.17, §III.13. States as one model a distinction the corpus had been making in pieces. **Motivating question (operator, 2026-08-06)**: if everything is encrypted at rest, what separates a secret from private information? **Answer: not sensitivity — permitted use.** Encryption at rest and the vault answer different threat models: FDE protects a powered-off device and offers nothing while the substrate runs, when any process running as the operator can read `~/ZeroPoint/`; the vault holds against that adversary because its key derives from Genesis and exists only in memory after a ceremony. **Three tiers, sorted by one test — does the substrate need to *think* about this, or merely *pass it along*?** **(1) Secrets** — possession confers authority to act as the operator; machine-consumed, rotatable, blast radius is action not disclosure. Custody: vault. Never admitted to cognitive context (R1 privilege invariant; standing correction `d267fe48`). Chain carries the *fact* of storage/access, never the value. **(2) Subject matter** — trajectories, decisions, chain history; often more personally revealing than any key, and the material cognition exists to reason over. Custody: chain + ontology, protected by signature and the Form's disk encryption. **Not vaulted, deliberately**: per-entry encryption would break officer queries, Cartographer materialization, and Claim 2 collective audit — the chain is protected by being signed, not by being unreadable. **(3) Refused** — §III.24 non-acquisition classes; no encrypted form of a keylogger is acceptable. **Boundary enforcement**: `zp-audit/src/scrub.rs` is the always-on point where Tier 1 material straying into a Tier 2 surface (a token in a command line) is redacted before the chain accepts it — the tier boundary made mechanical. **Edge cases resolved**: a `DATABASE_URL` with an embedded password is Tier 1 entire; a key's *existence* is Tier 2 while its value is Tier 1, which is what names-only `list()` expresses. **Onboarding implication**: `onboard/credentials.rs` and `deep_scan.rs` already assign custody — the gap is that onboarding is a one-shot ceremony while custody is a continuous invariant, so the April 2026 vault establishment silently evaporated with nothing re-checking. Splits into *onboarding assigns custody* (exists) and *boot invariants verify it held* (does not). **Supplies four custody-derived boot invariants**, including `vault_nonempty_if_tools_were_governed` — six `.env.zp` files alongside an empty vault was an observable contradiction for four months. Notes that `SUBSTRATE-BOOT-INVARIANT-CEREMONY`'s existing `vault_key_composes_with_provider` **passes** the 2026-08-06 defect, because it tests capability where the failure was delivery. **§9 added 2026-08-11 — vault lifecycle and the copy prohibition**, after three byte-identical `vault.json*` copies were found in the runtime home distinguishable only by mtime, and the older was nearly restored over the newer. Argument: a vault `.bak` is **rollback reached through the filesystem** (§III.20 violation), and for a secrets store rollback is a security regression rather than recovery because it resurrects rotated and revoked credentials; each copy is additionally one more offline-attackable ciphertext. **No vault copies in the runtime home, ever**, enforced by four mechanisms — atomic write (temp/fsync/rename, removing the crash-safety reason for a `.bak`), `vault:mutated` receipts carrying tier + key count + before/after hash (removing the did-it-change reason), a Genesis-signed `vault:exported` ceremony to a destination outside the runtime home as the *only* legitimate second copy, and a bedrock `no_vault_siblings` invariant making the prohibition enforced rather than agreed. Per §III.18, also specifies a **governed absent-vault test mode**, since the copies existed precisely because testing bedrock's vault detection had no path but `mv`. **Re-import left open** — legitimate DR that reintroduces credential resurrection; sketched as a ceremony anchoring `vault:imported` with the export's age and hash, explicitly not to be built as a quiet inverse of export.

- **[`design/TRIAGE-FOR-COHERENCE-2026-07.md`](design/TRIAGE-FOR-COHERENCE-2026-07.md)** — Discipline. Supplies the operation the corpus has been missing: coherence appears throughout as a *state to be checked* (observer, emission, spec-implementation) with no rule deciding **what gets checked next**, and no way to distinguish a claim verified from one nobody has ever examined — both present as silence. Term coined by Ken 2026-07-27 after a session in which seven divergences were all found incidentally. **Ranking rule**: priority rises with blast radius (cost of the belief being wrong — tier of the claim, count of elaborating documents, and sharply if it enters agent context as identity rather than reference), rises with staleness risk (C9's corrected trigger: *inputs changed*, not time passed), and falls with verification cost. **The inversion**: cheap-to-verify is *promoted* rather than deferred, unlike medical triage — a bounded known cost can wait, an unresolved cheap unknown is a standing liability against every later decision that reads the artifact. **Four states**: `untriaged` (the default, and the one that does not currently exist), `coherent` (naming the commit checked against), `divergent` (carrying a tie-off), `stale` (derived, never issued) — with the recursion that a verdict is itself a derived artifact subject to C9, so a verdict without a commit is indistinguishable from a guess. **Coverage** = fraction of load-bearing claims holding a non-stale verdict, derived from the connection object rather than authored; once measurable, the uncovered set *is* the queue and stops depending on anyone noticing. Six outcomes (TC1–TC6), four open positions. **First run 2026-07-27**: coverage is **331 of 987 declared connections — 33.5%** at commit `b548fb8` across 122 governed documents. ## Update conventions

**When a canonical claim changes**, amend KEEL and the affected Tier-2 elaborations. Update this index if the tier structure changes (new Tier-2 doc lands, existing doc reclassifies).

**When a new elaboration lands**, add it to the appropriate Tier-2 group in this index with a one-line description of its scope and the KEEL section it elaborates.

**When a working artifact lands** — a session brief, a working log, an edit sheet, an operating brief — add it to *Working artifacts* instead. It is tracked, it is indexed so it is reachable, and it is not corpus: nothing canonical may depend on it. The test is whether the document makes a claim about the substrate or merely records the doing of work.

**When an investigation or program lands**, add it to *Investigations and programs* instead — it has no KEEL section to name, and that is the point of the category rather than a defect in the document. `corpus-lint index-missing` enforces this for anything declaring a date on or after 2026-07-10; a document that predates the index convention stays in the measurement and is not retro-indexed.

**Handoffs are local notes, not corpus.** `docs/handoffs/` is gitignored by decision (2026-07-27), and stays that way. Twenty-four corpus documents cite seventy-one handoff files between them; from any clone but the operator's, those paths do not resolve. That is accepted — a handoff is a reasoning trail for whoever was there, not a shared artifact — but it means a citation to `docs/handoffs/*` should be read as *a local note exists*, never as a resolvable reference, and nothing canonical may depend on one to be understood.

**The exception, and the test for it — 2026-07-29.** A handoff gets promoted into `docs/design/` when something *shipped* depends on it to be understood. Three were promoted on that date because five discipline pins — build-failing rules — cited them as rationale: the rule travelled with the repo and the reason for it did not. Companion *investigation* documents were deliberately left behind, because nothing shipped cites them. The test is not importance or length; it is whether code in the repo points at the file.

**Open positions are notes, not a backlog — 2026-07-29.** Documents in this corpus end with open positions (ML-A..E, AL-A/D, SF-A..E, TC A–D and others). None of them blocks anything. An open position records that nobody has examined a question — which was the state before it was written down, and writing it down created no work. Read them when the surrounding area is being touched anyway; do not read the list as outstanding tasks. A position that genuinely blocks work says so explicitly and names what it blocks.

**When a doc becomes historical**, move it to Tier 3 in this index. Its front matter should get a Historical-status header pointing at KEEL for canonical claims. Don't delete — freeze at authoring frame.

**Never amend Tier 3 docs for corpus pivots.** If a pivot exposes a gap in Tier 1 or Tier 2, close the gap there. The historical doc stays as-is.

**Working principles and workflow heuristics stay in CLAUDE.md.** They're behavioral rules for how work happens, not substrate claims. This index does not duplicate them.
